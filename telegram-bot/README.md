# Telegram-бот «Запасной аэродром»

Отдельный Telegram-бот `@zapasnoy_aerodrom_bot` на Cloudflare Workers + D1. Он не использует конструкторы и не зависит от кода бота, который уже принимает лиды с сайта.

## Что реализовано

- несколько гайдов с deep-link `?start=<guide_key>`;
- проверка подписки через `getChatMember`;
- уникальная выдача PDF по паре «пользователь × гайд»;
- живой счётчик уникальных выдач под всеми опубликованными постами;
- отдельная форум-тема на каждого лида с названием `ПРЕФИКС · Имя #TelegramID`;
- пересылка сообщений лида в его тему и ответ команды из темы в личный чат;
- темы другого бота игнорируются: ответ разрешён только в темах, которые есть в собственной таблице `user_topics` этой D1;
- владельцы и отвечающие сотрудники проверяются только по числовым Telegram ID;
- меню владельца: статистика, публикация с подтверждением, отложенная публикация, добавление гайда, подтверждаемая рассылка и отмена;
- очередь webhook-обновлений в D1, cron каждую минуту, повторные попытки Telegram/D1 с backoff;
- отдельные таблицы для пользователей, гайдов, активаций, выдач, постов, тем, расписания, рассылок, follow-up и входящих webhook-событий.

## Безопасность

`BOT_TOKEN` и `TELEGRAM_WEBHOOK_SECRET` отсутствуют в исходниках и Wrangler-конфигурации. Они задаются только командами `wrangler secret put`. Скрипт `scripts/configure-telegram.sh` запрашивает токен скрытым вводом, генерирует webhook secret в памяти и не создаёт файл с секретами.

Если токен когда-либо был отправлен целиком в чат, его нужно отозвать через BotFather и создать новый. Первая числовая часть токена сама по себе является ID бота, а не полным секретом.

## Недостающие значения

Перед рабочим запуском нужны:

1. полный токен (вводится локально скрытым вводом, не присылается в Git и конфиг);
2. Telegram ID хотя бы одного владельца для `OWNER_USER_IDS`;
3. `CHANNEL_ID` и ссылка-приглашение/публичная ссылка канала;
4. ID форум-группы команды;
5. Telegram ID сотрудников для `SUPPORT_REPLY_USER_IDS`;
6. данные хотя бы одного гайда и Telegram `file_id` PDF/изображения.

Ссылка на консультацию уже настроена: `https://zapasnoy-aerodrom.com`.

## Как узнать ID

- Свой ID: после подключения бота отправить ему `/userid` в личном чате.
- ID форум-группы: добавить бота в группу и отправить `/chatid` в общей теме. При включённом Privacy Mode бот может не увидеть обычные сообщения, поэтому режим нужно отключить через BotFather.
- ID канала без публикации служебного поста: переслать любой пост канала боту в личку и ответить на пересланное сообщение командой `/chatid`. Если Telegram скрывает источник, ID нужно посмотреть через Bot API после назначения бота администратором.

По одной invite-ссылке `https://t.me/+s-NJAPfPyR1jM2Vi` вычислить числовой ID закрытой группы нельзя.

## Что сделать в Telegram

1. В BotFather открыть `/setprivacy` → выбрать `@zapasnoy_aerodrom_bot` → `Disable`.
2. Добавить бота администратором канала и выдать право публиковать сообщения. Это также требуется, чтобы `getChatMember` надёжно проверял подписку других пользователей.
3. Добавить бота в существующую закрытую форум-группу.
4. Выдать боту право управления темами (`can_manage_topics`) и право отправлять сообщения.
5. Не менять права, темы и настройки уже работающего бота сайта.
6. Получить числовые ID командой `/chatid`, а ID владельцев/сотрудников — `/userid` в личном чате.

## Развёртывание

Все команды выполняются из папки `telegram-bot`.

```sh
npx wrangler d1 create zapasnoy-aerodrom-bot-db
```

Полученный `database_id` нужно записать в `wrangler.jsonc`, затем:

```sh
npx wrangler d1 migrations apply zapasnoy-aerodrom-bot-db --local --persist-to=/private/tmp/prodigital-work/cloudflare/zapasnoy-aerodrom-bot
npm run check
npx wrangler deploy --dry-run
npx wrangler d1 migrations apply zapasnoy-aerodrom-bot-db --remote
npx wrangler deploy
sh scripts/configure-telegram.sh https://zapasnoy-aerodrom-bot.<account>.workers.dev
```

Скрипт webhook не публикует посты и не запускает рассылки. Публикация и рассылка возможны только владельцем и только после отдельного нажатия кнопки подтверждения.

## Добавление гайда

В личном чате владельца:

1. загрузить PDF и изображение боту;
2. ответить `/fileid` на каждый файл;
3. открыть `/admin` → `➕ Добавить/обновить гайд`;
4. прислать JSON по показанному шаблону;
5. вернуться в `/admin`: у гайда появятся отдельные кнопки публикации и расписания.

## Проверка после запуска

```sh
curl https://WORKER.workers.dev/health
curl --silent "https://api.telegram.org/bot<TOKEN>/getWebhookInfo"
```

В Telegram: `/userid`, `/chatid` в форум-группе, затем тестовый deep-link для чернового гайда. Тестовая тема создаётся только после явного обращения пользователя к боту; пост в канал и рассылка для проверки не нужны.
