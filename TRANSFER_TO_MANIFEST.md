## Перед началом переноса

1. Получить от клиента сообщение, что проверка сайта завершена и он готов принять владение репозиторием.
2. Убедиться, что клиент вошёл в `manifestteam21-commits` и имеет доступ к DNS домена в Spaceship. Проверить, что в целевом аккаунте нет репозитория с именем `north-cyprus-relocation`.
3. Сверить текущий коммит `main`, успешный запуск Pages, адрес сайта и DNS. Если сайт или публикация уже не работают, сначала устранить проблему.
4. Согласовать короткое время для совместной проверки: после переноса может потребоваться перенастройка Pages, DNS и HTTPS. Нулевой простой заранее не гарантируется.

## Перенос и проверка

1. Нынешний владелец открывает **Settings → General → Danger Zone → Transfer ownership** и указывает `manifestteam21-commits`. GitHub сохраняет историю Git, задачи и pull request; старый владелец автоматически становится соавтором. Клиент принимает приглашение из письма GitHub в течение 24 часов.
2. В новом расположении репозитория проверить **Settings → Pages**: источник **GitHub Actions**, пользовательский домен `zapasnoy-aerodrom.com`, HTTPS. Если требуется, повторно выполнить процесс публикации.
3. В Spaceship поменять только `www` CNAME на `manifestteam21-commits.github.io`; записи A корневого домена оставить на GitHub Pages. Точное состояние DNS перепроверить перед сохранением.
4. Подтвердить домен Pages в профиле нового владельца с помощью TXT-записи, которую выдаст GitHub. Подтверждать домен за новым аккаунтом **до** передачи нельзя: GitHub может освободить его от сайта прежнего владельца.
5. Проверить HTTPS, перенаправление с HTTP и `www`, главную страницу, блог, статью, изображения и стили. Отдельным тестовым лидом проверить отправку формы в таблицу и Telegram, затем удалить или пометить тестовые данные по договорённости.
6. Обновить ссылки на репозиторий в инструкции и рабочих документах. Отдельно подтвердить доступ клиента к Spaceship, Google-таблице, Apps Script, аналитике и инфраструктуре Telegram-бота: владение GitHub их не передаёт.

GitHub перенаправляет старые ссылки на репозиторий, но [не перенаправляет GitHub Pages](https://docs.github.com/en/repositories/creating-and-managing-repositories/transferring-a-repository). Правила [DNS и пользовательского домена](https://docs.github.com/en/pages/configuring-a-custom-domain-for-your-github-pages-site/managing-a-custom-domain-for-your-github-pages-site) и [подтверждения домена](https://docs.github.com/en/pages/configuring-a-custom-domain-for-your-github-pages-site/verifying-your-custom-domain-for-github-pages) описаны в справке GitHub.
